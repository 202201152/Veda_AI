VedaAI — AI Teacher's Toolkit (Assessment Extraction & Answer Mapping)
Version 2.0  ·  Draft  ·  Hiring assignment submission — updated to match the provided VedaAI mockup
What changed in v2.0: the product is renamed from the standalone “AssessAI” concept to “AI Teacher's Toolkit” — a module inside the existing VedaAI teacher platform, per the provided design mockup. The core problem, users, and MVP scope are unchanged; the app flow and assumptions sections below are updated to reflect the surrounding app shell (sidebar, top bar, teacher profile) and the inline AI-feedback interaction shown in the mockup.
1. Problem Statement
Grading handwritten answer sheets is a manual, slow, error-prone process. A teacher has to hold a printed question paper in one hand and a student's handwritten answer sheet in the other, cross-referencing every question number, hunting for where an answer starts and ends, and judging quality — all without any tool support.
This gets harder in exactly the situations that happen constantly in real exams: a student answers questions out of order, skips one entirely, or writes an answer that spills onto a later page. There's no fast way to see, at a glance, which question maps to which block of handwriting, or which questions were left blank.
The core problem is the lack of an automated bridge between a printed question paper and a handwritten answer sheet — every check today is manual, visual, and slow.
2. Target Users
Primary user — Teacher / Evaluator
Uploads one question paper and one student's answer sheet at a time, reviews the results, then repeats for the next student.
Opens the AI Teacher's Toolkit from inside the VedaAI platform they're already working in — the mockup shows a signed-in teacher (name and school visible in the sidebar). This feature does not add its own login: see Section 8 and the Security & Access Document for how that reconciles with the assignment's “no authentication” constraint.
Comfortable with everyday web apps but not necessarily technical — the interface needs to make a complex AI pipeline feel like a simple three-click tool.
3. Product Vision
Upload a question paper and one student's answers — instantly see what was answered, where, and how well, without ever flipping between two documents.

6. Success Metrics
Metric
Why it matters / target
Question extraction accuracy
Every question (including sub-parts) is found, in the correct printed order, with numbering preserved — target as close to 100% as achievable on a clean scan.
Answer mapping accuracy
Answers land on their true question, verified by manual spot-check, including out-of-order cases.
Highlight accuracy
The highlighted region visually overlaps the actual handwritten answer on the page.
Unanswered/unmatched detection
No unanswered question is missed; no unmatched answer is silently force-matched to the wrong question.
End-to-end processing time
One question paper + one answer sheet processes in well under a minute for a typical exam length.
7. What the MVP (Version 1) Looks Like
The MVP is the smallest version that fully solves the core evaluation criteria: accurate extraction, accurate mapping, correct highlighting, and sound edge-case handling. It includes:
Single question paper + single answer sheet upload (PDF or images).
Full core pipeline: question extraction → answer extraction → mapping → highlighting.
Unanswered and unmatched detection, both clearly surfaced in the UI.
AI grading and feedback, clearly labeled as AI-generated rather than a verified rubric result, shown inline per question plus an overall summary.
The VedaAI app shell (sidebar, top bar, breadcrumb) around the toolkit's own screens, with static/placeholder profile and school data — no real accounts system.
In-memory only — no database, results reset on refresh, exactly as the assignment allows.
Deployed to a live, publicly accessible URL on Vercel.
8. Deliberately Not Building — Assumptions & Limitations
Stated upfront so they can be copied directly into the submission form's “assumptions and limitations” field.
No login/accounts — anyone with the live link can use the tool, per the assignment's “no authentication required” constraint. The teacher name, avatar, and school shown in the sidebar are static placeholder data matching the provided mockup, not a real signed-in session — see the Security & Access Document.
No database — nothing is saved server-side beyond the life of a single request; refreshing the page clears all results.
No teacher-provided answer key or rubric in v1 — grading is the AI's own best-effort judgement of answer quality, not a verified match against a ground-truth key. This is stated clearly in the UI so grading is never mistaken for an authoritative result.
No batch/multi-student processing in v1 — one question paper and one answer sheet per run.
No manual correction of extracted text or AI-assigned marks in v1.
Assumes reasonably legible handwriting and a reasonably clean scan or photo — very poor image quality will reduce extraction accuracy, which is a limitation of any handwriting-OCR approach, not just this tool.
Assumes question numbering in the printed paper is machine-readable (printed text, not handwritten annotations on the question paper itself).
English-language content is assumed for v1.
The surrounding VedaAI sidebar/top-bar shell is treated as existing platform chrome to match visually — rebuilding VedaAI's other sections (Home, My Classroom, Assignments, My Library) is out of scope; only their nav entries are rendered.
