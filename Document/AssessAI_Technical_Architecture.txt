TECHNICAL ARCHITECTURE DOCUMENT
VedaAI — AI Teacher's Toolkit (Assessment Extraction & Answer Mapping)
Version 2.0  ·  Draft  ·  Companion to the Product Requirements Document
What changed in v2.0: adds a components/shell/ layer (Sidebar, TopBar, Breadcrumb, SchoolProfileCard) so the four-route pipeline can render inside the VedaAI app shell shown in the updated mockup. The pipeline itself — tech stack, data model, and the four API routes — is unchanged from v1.0; the shell components consume static placeholder data only, per the Security & Access Document's no-accounts constraint.
1. Recommended Tech Stack
No database or authentication is required or wanted here, so the stack is deliberately lean: one Next.js app, one AI provider, and nothing else to operate or pay for.
Layer
Technology
Why this choice
Frontend
Next.js 15 (App Router) + React 19
File-based routing and Route Handlers let the whole app — UI and API — live in one deployable project, matching the assignment's Next.js recommendation.
Backend / API
Next.js Route Handlers (Node.js runtime)
Four small API routes (extract-questions, extract-answers, map-answers, grade) handle the pipeline; no separate server needed.
AI model
Google Gemini (gemini-2.0-flash, via @google/generative-ai)
Chosen for its free tier, strong handwriting OCR, native multi-image/PDF input, and reliable structured JSON output — all four pipeline stages can be one model.
PDF rendering (display only)
pdfjs-dist (client-side)
Rasterizes each uploaded PDF page into an image in the browser so the highlight overlay has something concrete to sit on top of. Separate from what's sent to Gemini, which can read PDFs natively.
Styling
Tailwind CSS
Fast, consistent implementation of the Frontend Specification Document's design tokens (including the v2.0 orange/charcoal/green palette) without hand-written CSS files.
Client state
React state (useState/useReducer)
All extracted data lives in memory in the browser tab for the duration of one session, including which sidebar/collapse state and which question is expanded — no external state library needed.
Data fetching
Native fetch, sequential per stage
Each pipeline stage is a distinct request, which is what drives the real (not simulated) processing progress bar. SWR's caching model isn't useful for a one-shot pipeline.
Hosting
Vercel
Zero-config Next.js deployment, matching the assignment's “must be deployed and accessible through a live URL” requirement.
Storage
In-memory only, per request
No database, per the assignment's constraints. Uploaded files and extraction results exist only for the life of a single request/response cycle. The shell's profile/school display is static, not stored.

4. API & Integration — Gemini Pipeline
Unchanged from v1.0. Four sequential API routes give the processing stepper real, verifiable stages instead of a fake timed animation.
4.1 POST /api/extract-questions
Aspect
Detail
Input
Question paper file(s) (PDF or images) as multipart form data.
Prompt intent
Extract every question in printed order; treat labelled sub-parts (11(a), 11(b)) as separate entries; preserve original numbering exactly as printed.
Output
Question[] as defined above, validated against the type before returning; malformed model output is retried once with a stricter prompt.
4.2 POST /api/extract-answers
Aspect
Detail
Input
Answer sheet file(s) (PDF or images).
Prompt intent
OCR every distinct handwritten block; detect any visible question-number label; return a normalized bounding box per block, and multiple boxes for one answer that spans pages.
Output
AnswerBlock[] as defined above.
4.3 POST /api/map-answers
Aspect
Detail
Input
The Question[] and AnswerBlock[] from the previous two calls.
Prompt intent
Match by detected label first; fall back to content/order reasoning for unlabeled or ambiguous blocks; explicitly list unanswered questions and unmatched answer blocks rather than force-matching.
Output
Mapping[] and UnmatchedAnswer[].
4.4 POST /api/grade
Aspect
Detail
Input
Matched question/answer text pairs from the mapping step.
Prompt intent
Score each answered question out of a configurable max, assign a correctness label, and write 1–2 sentences of feedback; unanswered questions are scored 0 locally without an AI call; one additional call produces the overall summary.
Output
Grade[] and one OverallSummary, clearly surfaced in the UI as AI-generated rather than a verified rubric result.

Configuration notes
The Gemini API key must only ever be read inside API routes (server-side) — never imported into a client component or bundled into browser JavaScript.
Because there's no database, nothing about a request should be stored in a module-level variable that could leak between concurrent users on the same serverless instance — every API route must derive its response purely from that request's own input.
File size and type validation happens twice: once client-side for instant feedback, and again server-side, since client-side checks alone can be bypassed.
The shell's teacher name/avatar/school fields (Section 2) are static placeholder data — hardcoded or passed as build-time props — and are never read from or written to any store, consistent with the no-accounts constraint.
